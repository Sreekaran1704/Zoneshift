# Security notes

ZoneShift uses only public NYC TLC data. This file records how credentials and execution are
protected, and the last security review (2026-10-15).

## Secrets

- Credentials live only in `.env` (repo root) and `orchestration/airflow/.env`, both gitignored and
  owner-readable only (`chmod 600`). The variable names are listed in the README; the Airflow file is generated by
  `make airflow-env` with a random Fernet key, JWT secret and admin password.
- dbt profiles read credentials from environment variables; `profiles.yml` is gitignored.
- Review: full git history and all pushable files scanned for API keys, tokens, private keys,
  Databricks hosts and passwords: none found. Evidence files under `docs/` contain no
  credentials or hostnames.

## Execution safety

- **Text-to-SQL agent:** three layers. (1) sqlglot guard: one read-only SELECT on five allowlisted
  marts, no table functions or file paths, enforced `LIMIT 1000`. (2) DuckDB opened read-only with
  `enable_external_access = false`. (3) `lock_configuration = true`, so settings cannot be changed.
  Probed with 16 attack queries (env/file reads, `SET`, `ATTACH`, `COPY`, `PRAGMA`, other schemas,
  multi-statement, comment tricks): none could read files, secrets or other schemas.
- **Airflow DAG:** every trigger parameter that reaches a shell command is validated against an
  allowlist/regex (bad input fails without retries) and shell-quoted. A test trigger with
  `types = "yellow; touch /tmp/pwned"` was rejected before any command ran.
- **Airflow stack:** UI/API bound to `127.0.0.1` only; postgres not exposed; local development
  only (no TLS).
- **CI:** `permissions: contents: read`; no secrets are used in CI.
- All `subprocess` calls pass argument lists (no shell); downloads use HTTPS and size checks; the
  shapefile zip is extracted with a path-traversal check.

## Dependencies

`pip-audit` on all requirement files: no known vulnerabilities except one accepted item.

| Package | Advisory | Status |
|---|---|---|
| oauthlib 3.3.1 (dev; via databricks-sql-connector) | PYSEC-2026-4114, timing side channel in server-side PKCE verification | Accepted: not reachable (client-only token auth). Cannot upgrade: databricks-sql-connector (latest 4.6.0) requires `oauthlib<4`. Re-check on connector updates. |

## Owner actions

- Rotate the Databricks token before it expires (2027-01-12) or if it is ever exposed; revoke it
  when the cloud deployment is no longer needed.
- Keep the GitHub repo free of `.env` files; GitHub secret scanning and Dependabot alerts can be
  enabled in the repo settings at no cost.
